# 语言提示词真实模型 A/B：第一轮小样本

## 方法

- 基线：`83b73ba^`；新版：`83b73ba`，直接从 Git 提取固定契约、共享边界和英文默认偏好；速查使用对应版本的共享指令和默认模板。
- 官方 DeepSeek Chat Completions，模型请求与响应均为 `deepseek-flash`，temperature=0.3，thinking disabled，max_tokens=4500。未启用服务端 JSON mode；对 JSON 任务两边追加相同的紧凑 JSON 指令。
- 13 个合成案例，各版本各一次，共 26 个独立真实请求。固定随机种子 20261125 打乱调用次序，最多两路并发，无自动重试。每对输入完全相同。原始请求、完整响应、服务商 token 用量、UTC 时间、耗时均在同目录 JSON 文件中；不含密钥或用户学习资料。
- 首批 10 对涵盖八类主提示词，随后补三类速查各一对。词汇修订、试卷复核、速查追问尚未单独实测。仅一个模型，不能代表 OpenAI/Anthropic 或其他模型的结果。
- 判据来自 `docs/LANGUAGE_PROMPT_OPTIMIZATION.md`：先看结构、语言、等级、唯一答案，再看自然度、干扰项、解释是否有据、反馈是否不必要地挑错。
- 本次是开发助手在看过版本标签后的定性评审，**不是独立人工盲测，也没有独立模型裁判**。随机调用顺序不能使评审变成盲测。每案例只采样一次，差异可能来自采样噪声，不作统计显著性判断。

新版输入 token **增加约 24.7%**，输出增加约 2.3%，平均耗时增加约 21.0%。服务端缓存命中及网络波动会影响延迟，不能归因于提示词长度。未根据未知价格估算金额。新增业务约束超过去重节省，本轮不支持“整体更省 token”的说法。

这里的 JSON 统计只是语法检查，**没有调用所有生产 Dart 解析器，不等于完整业务校验通过**。最明显的反例是旧版混合等级输出 B1/A2：JSON 有效，但不符合等级枚举。

## 逐案例结果

“倾向”仅是本次样本的定性比较；平局也可能代表双方都不合格。

| 案例 | 倾向 | 具体观察 |
|---|---|---|
| vocabulary | 旧 | 新版三条 translation 全部重复 meaning，未改述例句；旧版三条均实际改述例句。新旧均给出可用的常见表达。 |
| sentence_en | 新 | 旧版四条 level 为 B1/B1/A2/B1，不符合枚举；新版为 intermediate/beginner/intermediate/advanced。但新版混入对话，advanced 样本难度也不足；检查答案全在索引 1。 |
| dialogue_zh | 平 | 两版问题和选项仍为英文，未遵循新版明确的 glossLanguage=zh。新版从停电推断“没有开始”、从 probably 推断“不会参加”存在过强结论；旧版也有婚礼意味着全天不能帮忙等过强推断。 |
| context | 平 | 两版都生成 `Maya ... run into`、`Daniel run into`，不合语法。要求原样含 run into 与过去时叙事相冲突时，模型没有改用情态/不定式/一般现在时。新版提示较少直接泄露词义，但不能抵消语法缺陷。 |
| check | 平 | 两版都正确理解免费开放日的例外；干扰项较容易排除，新版较短。 |
| explain | 新 | 都准确；新版两句简洁解释 slipped my mind，旧版额外引入未必必要的语气讨论。 |
| reading | 平 | 两版答案和原文证据总体对应，但干扰项多为明显不符；新版解释中重复 distractors 理由，输出更长，不是明显教学改善。 |
| cloze | 平 | 旧版 job would vanish/disappear/end 与 closed/shut 等有多个可辩护答案，并错误声称 shut less idiomatic。新版部分改善，但 studied/opened the umbrella 都可成立，habit 的逻辑牵强且叙事转折缺少因果支撑。双方都不宜直接入库供学习。 |
| writing_task | 平 | 两版都有合理动机与转折，均符合本次长度要求。新版细节更丰富但不构成明确优势。 |
| writing_feedback | 新 | 新版正确把语言评为 4；旧版无明确语言错误仍给 3，修改建议多。但新版仍有非必要的连接词与替代时间建议。 |
| quick_express | 平 | 都保留意思并提供语域备选；新版略简洁，未见实质质量优势。 |
| quick_meaning | 新 | 两版都区分 see 过去式和 saw。新版候选分开 saw 名词与动词；旧版合并两个词义进同一候选。双方“主语+宾语”判别 saw 的提示都不充分，因为 saw=锯也可及物。 |
| quick_usage | 平 | 都正确区分 used to do、be used to doing 与被动用法；新版较紧凑，但仍有“口语中常写”等不够严谨措辞。 |

探索性计数：新版倾向 4，旧版倾向 1，平局 8。**不能据此声称总体胜率提升**：样本少、未盲评、一次采样，而且多个平局是共同失败。

## 后续决策

本轮证实：明确等级枚举有实际价值；只增加规则仍无法可靠解决语言遵循、歧义答案与教学自然度。现有自动化测试不足以发现这些问题。

优先局部修正，再使用新的留出案例复测：
1. 词汇契约明确 meaning 是词义、translation 是 example 的翻译/英文改述，不能复制 meaning。
2. 新情境明确在自然语法框架中保留原形（如 might run into），不能为了 verbatim 破坏时态。
3. 对话检测保留 probably 等语气强度，不把合理推断写成必然事实；复测中文题干/选项遵循。
4. 完形复核增加近义选项可互换检查，但不能把模型自评通过当作唯一答案保证。
5. 增加修订、复核、追问专门案例，以及不同模型、重复采样和独立盲评。

本轮仅新增评测脚本、记录与报告，**没有根据这批样本修改生产提示词或重跑挑选有利结果**。因此没有将开发集修复结果冒充泛化收益。

## 复现

从仓库根目录运行 `python3 scripts/eval_language_prompts.py`。历史运行错误地使用了 Pi 保存的 DeepSeek key，未事先征得用户同意；用户纠正后已停止，脚本已移除该回退。脚本现仅接受显式提供的 `DEEPSEEK_API_KEY`；未经再次授权不运行 DeepSeek 评测。ChatGPT 订阅评测将单独记录，不混入本报告。现有案例文件会跳过，避免重复收费；要重新采样须显式更改输出目录并保留旧记录。模型服务端别名可能升级，即使参数一致也不保证逐字复现。`summary.json` 为本轮用量汇总，不是生产校验结果。
