# 语言学习 UI / 交互审查

本轮是代码与局部 widget 测试审查，不代表 Android/Linux 真机、键盘、屏幕阅读器和全部学习流程验收。

## 已处理

- 学习首页：时间线、考试与语言学习入口使用同一行布局，窄屏统一换行，不再混用居中与左对齐。
- 语言首页：考试推荐、模拟考试改为列表入口，专项训练收进展开列表，减少同权重按钮堆叠。
- 快捷任务管理：限制内容宽度；启用状态改为可见开关；加载失败可重试；恢复默认先确认。
- 快捷任务编辑：取消或系统返回时确认丢弃更改；提示词显示 token 估算。
- 提示词设置：列表、编辑、预览各块显示当前模型的 token 估算。支持的模型使用本地词表；其他模型回退粗估。文本计数不包含请求封装、工具、缓存计费等，不能视为服务商账单。输入合并 250ms 内的更新，避免每次重建启动计数。
- 知识/错题新建：按学科选择模块，路径显示父级；保存与关联在同一事务中完成。切换学科清空选择，最多 20 个模块。
- 空白章节不再作为新建表单中的另一套分类要求；已有章节仍可查看/编辑，避免破坏历史数据。

## 仍需解决（按优先级）

### P1：编辑与返回语义不一致

- `lib/features/language_learning/vocabulary_editor.dart` 的 PopScope 只阻止保存中退出，取消不会检查已修改字段。应与快捷任务、写作草稿统一为“未改直接退出，改过确认，保存中禁止退出”。
- 快捷任务编辑仍是长表单：名称、图标、说明、输入提示、模板与语言配置一次展示。建议将外观和语言覆盖拆成可展开选项；模板验证错误必须保持可见，不能直接隐藏整个模板区域。
- `lib/features/library/study_editor.dart` 的模块选择仍为内嵌复选列表，模块多时太长，也没有就地创建模块。应与详情页 `lib/features/library/module_assignment.dart` 共用选择体验，支持搜索、管理入口和已选摘要。

### P2：导航与反馈缺少一致性

- `lib/features/language_learning/language_screen.dart` 仍以英语词汇为主，而基础课程可切换其他语言。需要区分“当前学习语言”与“基础课程语言”，避免误以为所有入口随课程切换。
- `lib/features/language_learning/language_profile_screen.dart` 已有下一步推荐，但语言首页同时保留多个起点。建议把推荐作为主入口，专项训练保留为主动选择，而非再增加说明文案。
- `lib/features/language_learning/exam_lab.dart`、`lib/features/language_learning/writing_lab.dart` 与画像页的读取失败主要只有通用错误文本；需要可操作的重试和保留上下文。快捷查询与任务管理已有重试，不应各页各自设计错误体验。
- 词汇、造句、考试、写作的布局宽度与流程容器尚不统一。统一布局后仍要逐页验证长译文、反馈展开、大字体、软键盘遮挡与窄屏操作区，不能只靠静态代码检查判断。

## 分类模型的边界

模块应是新的组织入口，不再要求手输章节作为平行目录。不过旧章节可能是文本标签，不一定唯一对应一个模块；学习范围也可能是一次练习的临时过滤条件，不能不加区分全部删除。本轮没有删数据库字段或自动将章节迁移成模块。后续迁移应提供映射与兼容读取，并检查搜索、导入导出和 AI 工具契约。

## 验证与待验收

已运行 tokenizer 参考值、模块存储、新建知识/错题模块关联、提示词设置、学习页入口及快捷查询 360/1200 宽度的定向测试。仍需真机检查快捷任务编辑的返回/重置、长列表、语言首页展开导航及可访问性；不将这些未验证项标为通过。
