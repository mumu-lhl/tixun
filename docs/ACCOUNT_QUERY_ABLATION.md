# 余额与订阅额度：缓存、自动查询消融

2026-11-15，先实验，后修改生产实现。仅使用本地 HTTP fixture，未访问真实账号。

## 实验

对 DeepSeek `ProviderBalanceClient`、ChatGPT `ChatGptUsageClient` 分别运行同一受控流程：第 0、1、2、8 分钟进入设置页，最后手动刷新一次。比较是否自动查询、是否复用五分钟内的成功结果；手动模式在需要新结果时模拟点击。统计真实客户端到隔离 HTTP adapter 的请求数，不测量真实网络延迟。

| 自动查询 | 短期缓存 | HTTP 请求 | 手动点击 |
|---|---|---:|---:|
| 否 | 否 | 5 | 5 |
| 否 | 是 | 3 | 3 |
| 是 | 否 | 5 | 1 |
| 是 | 是 | 3 | 1 |

两个服务结果一致。仅缓存减少重复请求，但仍需手动取得新结果；仅自动查询减少点击，却不减少重复请求。组合满足这两个目标。数字只适用于上述模拟流程，不代表线上请求比例或成本节省。

## 最小实现

- 一个单结果内存缓存：五分钟有效，合并未完成请求，失败保留上次成功值；无计时器、磁盘缓存、后台轮询、LRU 或可配置策略。
- 客户端保留协议与身份边界：DeepSeek 按端点及 Key 指纹隔离，ChatGPT 按账号操作版本隔离；旧账号的迟到响应不回填当前缓存。
- 控制器保留客户端；页面进入时读取，缓存仍新鲜则不发请求。手动刷新绕过有效期；过期或失败的旧结果显示查询时间及提示，不冒充实时结果。
- 无已保存 Key、未连接账号或演示模式不自动查询。输入未保存 Key 时不自动发送；已有显式手动查询能力保留。

临时四组实验脚手架已删除，不将其固化为长期测试矩阵。保留缓存生命周期/并发/身份隔离、两种协议身份绑定，以及真实设置页进入、重入、刷新失败和跳过条件的行为回归；不加入像素 Golden、轮询或真实网络测试。架构说明同步更新了原有“仅手动查询”约定。
